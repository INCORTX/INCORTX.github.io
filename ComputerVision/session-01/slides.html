What a computer sees

A computer sees numbers, not objects

what you see

tap or hover a pixel

imageภาพa grid of numbers — here 12 × 12 = 144 pixels
pixelพิกเซลone number: 0 = black … 255 = white
Try itWhat is the value at row 5, column 5? Is that pixel dark or bright?
Answer30 — near 0, so dark: the diagonal of the “N”.

Here row 0, column 0 is the top-left pixel, as in NumPy and OpenCV. Tools differ: MATLAB counts from 1, OpenCV and PIL take points as (x, y) = (column, row), and a plot’s y-axis points up.

🇹🇭 ชี้หรือแตะช่องใดก็ได้ — ช่องเดียวกันเรืองทั้งสองฝั่ง · Try it: row 5, col 5 ให้เวลา 30 วิ (30 → มืด เส้นทแยงของ N) · ย้ำ นับจาก 0

🇬🇧 Hover or tap any cell — the same cell lights up on both sides. Try it: row 5, column 5? 30 s (30 → dark, the N's diagonal). Stress: count from 0.

Why vision is hard

Same “N”, new light — every number changes

shaded = what the rule calls ink

Normal light → now

Background · row 0, col 0
220 → 220
Stroke · row 5, col 5
30 → 30
A fixed rule

“value below 100 = ink”

You still read “N” at every light level — the numbers, and any fixed rule on them, do not. Viewpoint, size and objects in front do the same. That is why a program has to be taught to see.

🇹🇭 ลาก slider แสงจาก 100% ลงไป: ตัวเลขทุกช่องเปลี่ยน กฎ "ต่ำกว่า 100 = หมึก" พัง แต่เรายังอ่าน N ได้ · ถาม: กฎแบบไหนจะใช้ได้? (ไม่มีกฎตายตัว ต้องสอนให้เรียนรู้)

🇬🇧 Drag the light slider down from 100%: every number changes and "below 100 = ink" breaks, yet we still read N. Ask: what rule would work? (no fixed rule — it must learn)

A little history

In 1966, vision was planned as a summer project

“The summer vision project is an attempt to use our summer workers effectively in the construction of a significant part of a visual system.” — Seymour Papert, MIT, 1966

The plan: three steps, one summer

1 · Find the objectsSplit the picture into objects and background
→
2 · Describe themThe shape and surface of each one
→
3 · Name themMatch each one to objects it already knows

Start easy: balls, bricks and cylinders on a plain background.

What happenedIt took far longer than one summer. Sixty years on, those three steps are still what computer vision works on — and what this course teaches.

🇹🇭 อ่านคำพูด Papert แล้วไล่ 3 ขั้น · ถาม: เสร็จใน summer เดียวไหม? (ไม่ — 60 ปีแล้วยังทำ 3 ขั้นนี้อยู่ และวิชานี้สอน 3 ขั้นนี้)

🇬🇧 Read Papert's line, then the three steps. Ask: done in one summer? (no — sixty years on, the same three steps, and this course teaches them)

Course design

Learning comes before geometry — on purpose

01Convolution → CNNThe filters you design by hand in session 3 are what a CNN learns by itself in session 4.
02Your project needs itAfter CNNs, ViT and CLIP in session 5, you start looking for a project topic — three weeks before it is due.
03Geometry is mathsMeasuring depth from two cameras or stitching a panorama uses fixed formulas — no training. After learning, you can tell when a formula beats a model.

🇹🇭 3 เหตุผลที่เรียน learning ก่อน geometry · เน้นข้อ 02: รู้จัก CNN, ViT, CLIP แล้วหลังคาบ 5 เริ่มหาหัวข้อโปรเจกต์ได้เลย (ส่งหัวข้อสัปดาห์ 8)

🇬🇧 Three reasons learning comes before geometry. Stress 02: after CNN, ViT and CLIP in session 5, start looking for a project topic (due week 8).

Course outcomes

By the end of the course you can

  1. Explain how an image is formed and what information is lost
  2. Compute the core operations by hand — convolution, CNN shapes, attention scores, corners, transforms, depth, IoU, optical flow
  3. Use pretrained models (CNN, ViT, CLIP, YOLO, SAM) and explain what each one does
  4. Relate two images through features and geometry
  5. Evaluate a vision system with the right metric — and name its risks
  6. Design and compare two or three solutions to a real problem

Proposal · week 11 · video + slides

  1. Problem pitch, refined — input, output, problem and challenge, updated after week 10
  2. Data — where the dataset comes from and how it was collected
  3. 4 techniques — each explained in depth: theory, why it fits here, one example picture
  4. Parameter study — every parameter, and how changing it changes the output
  5. 2–3 solutions — workflow, pros and cons of each
  6. Creativity — an original idea, or a strong literature review
  7. Slides — 30+ pages, page numbers, at least one picture, no page over 6 lines

  10. Q&A — questions from the instructor and classmates
  11. On time — video and slides handed in by the deadline

Demo · week 14 · slides + notebook + video

  1. Accuracy — a metric that fits the problem, and why; same data for every solution
  2. Speed & resources — time, memory or parameter count of every solution
  3. Per-solution analysis — what each one got and why, using those numbers
  4. Parameter settings — the values each solution used, and why
  5. Overall analysis — the solution you pick and why; failure cases and limits
  6. Future work — what you would try next, and why
  7. Creativity — an original idea, or a strong literature review
  8. Notebook + live demo — one file, runs start to finish, every cell explained live
  9. Clean code — a section per solution, clear names, no repeated code
  10. Slides — 20+ pages, page numbers, at least one picture, no page over 6 lines
  11. Slide design — clear pictures and charts, consistent layout, a story that flows
