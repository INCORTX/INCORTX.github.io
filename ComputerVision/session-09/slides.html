A · Optical flow

Motion field vs optical flow

Motion field: how each 3D point really moves, projected onto the image. Optical flow: how the brightness pattern moves on the image. A camera only sees the second.

Usually they agree: walkers, the cyclist. Not always:

  • the LED sign: its letters slide 12 px left in 6 frames — flow, yet the sign never moves;
  • a smooth ball spinning in place — it moves, the image does not: no flow;
  • a cloud over the sun — brightness changes, nothing moves.

🇹🇭 ชี้ภาพสี: คนเดินซ้ายเป็นฟ้า เดินขวาเป็นแดง · ป้ายไฟวิ่งก็เป็นสีฟ้า ทั้งที่ป้ายไม่ขยับ — ตัวอักษรเลื่อน 12 px ใน 6 เฟรม (วัดจาก profile คอลัมน์ของพิกเซลแดง) · ลูกบอลสีเรียบหมุนอยู่กับที่: motion field ไม่เป็นศูนย์ แต่ flow = 0 · เมฆบังแดด: flow ไม่เป็นศูนย์ motion = 0

🇬🇧 Point at the colours: people walking left are cyan, right red. The LED sign is cyan too, yet it never moves — the letters slide 12 px in 6 frames (measured from the red-pixel column profile). A smooth ball spinning in place: motion field non-zero, flow zero. A cloud over the sun: flow non-zero, motion zero.

A · Optical flow

Brightness stays, position changes

Same brightness, new place. Expand to first order (a tangent line):

$$I(x{+}u,\,y{+}v,\,t{+}1)=I(x,y,t)$$$$\Rightarrow\quad I_x u+I_y v+I_t=0$$
Session 3, slides 28–29: Iₓ and I_y are the image gradient — taken after smoothing (σ = 2 here).

Worked example · u = 2, the steepest pixel

Iₓ = (101.4 − 79.3) ÷ 2 = 11.05 · Iₜ = 69.1 − 90.4 = −21.3 · u = −Iₜ ÷ Iₓ = 21.3 ÷ 11.05 = 1.93 ≈ 2

🇹🇭 ที่มา: ความสว่างเท่าเดิมแต่ตำแหน่งเปลี่ยน → Taylor อันดับหนึ่ง → Iₓu + I_yv + Iₜ = 0 · กราฟคือแถวจริงของเฟรม (ยางล้อหน้ามืด → ถนนสว่าง, blur σ 2) · ลาก u: 0.5–2 ประมาณได้ดี · 4 ได้ 3.2 · เกินความกว้างของทางลาด (~8 px) ค่าติดที่ 3.8 · คนปั่นจริงเลื่อน 30 px ต่อเฟรม → สมการนี้มองไม่เห็น → B (coarse-to-fine) · ย้อนคาบ 3 หน้า 28–29

🇬🇧 Where it comes from: same brightness, new position; first-order Taylor gives Iₓu + I_yv + Iₜ = 0. The curve is a real row of the frame (dark front tyre → light road, blurred σ 2). Drag u: 0.5–2 estimate well; 4 gives 3.2; past the ramp's width (~8 px) the estimate sticks at 3.8. The real cyclist moves 30 px per frame — invisible to this equation → B (coarse-to-fine). A · Optical flow

One equation, two unknowns: the aperture problem

One equation, two unknowns: it fixes only the motion along ∇I = (Iₓ, I_y), across the edge — the normal flow:

$$u_\perp=\frac{-I_t}{\lVert\nabla I\rVert}\quad\text{along}\quad\frac{\nabla I}{\lVert\nabla I\rVert}$$

Worked example · the default

n = (0.71, 0.71) · true (2, 0) · u⊥ = 2 × 0.71 = 1.41 → seen 1.41 × n = (1.0, 1.0)

Motion along the edge is invisible: the aperture problem.

🇹🇭 เริ่มรูปิด: แท่งดูเหมือนเลื่อนเฉียงขึ้นขวา (ตั้งฉากกับแท่ง) · กด Open the hole: เห็นปลายแท่ง → จริง ๆ เลื่อนไปทางขวา · หมุน true motion: ภายในรูเห็นแต่ส่วนที่ตั้งฉากกับแท่ง · ถ้า motion ขนานกับแท่ง: ในรูนิ่งสนิท · ต่อ B: มุม (สองทิศ) แก้ปัญหานี้

B · Lucas–Kanade

Assume a small window moves together

one pixel: a line of possible (u, v) · three pixels: the lines meet at one answer

Assume every pixel in a small window moves the same: each adds one equation.

$$\begin{bmatrix}I_{x1}&I_{y1}\\ \vdots&\vdots\\ I_{xn}&I_{yn}\end{bmatrix}\!\begin{bmatrix}u\\v\end{bmatrix}=-\begin{bmatrix}I_{t1}\\ \vdots\\ I_{tn}\end{bmatrix}\quad A\mathbf{u}=-\mathbf{b}$$

More equations than unknowns: make Σ(Iₓu + I_yv + Iₜ)² smallest (session 4, slides 12–13: a squared error) → AᵀA u = −Aᵀb.

Worked example · the picture

p₁ (2, 0, −2) · p₂ (0, 1, −3) · p₃ (1, 1, −4) → AᵀA = [5 1 / 1 2] · −Aᵀb = (8, 7) · det 9 → u = (2·8 − 1·7) ÷ 9 = 1 · v = (5·7 − 1·8) ÷ 9 = 3

🇹🇭 ที่มา: หน้าต่างเดียวกันเลื่อนเท่ากัน → หนึ่ง pixel หนึ่งสมการ → least squares (ย้อนคาบ 4 หน้า 12–13 loss) → AᵀA u = −Aᵀb · ภาพขวา: แต่ละ pixel = เส้นหนึ่งเส้นในระนาบ (u, v) · เส้นตัดกันจุดเดียว = คำตอบ · ตัวอย่างไม่ซ้ำ Try it หน้า 16

🇬🇧 Where it comes from: the whole window moves together, so each pixel adds one equation; least squares (session 4 slides 12–13, the loss) gives AᵀA u = −Aᵀb. Right: each pixel is a line in the (u, v) plane; where the lines meet is the answer. The example differs from slide 16's Try it.

C · Tracking

Live: what moved?

street clip
$$\text{moving}(x,y)=\big|\,I_t(x,y)-I_{t-1}(x,y)\,\big|>\tau$$

Subtract the last frame; keep the pixels that changed by more than τ. No model, no training.

Worked example · two pixels, τ = 25

120 → 150: |150 − 120| = 30 > 25 → moving · 120 → 135: 15 ≤ 25 → still

It breaks when the light changes (everything “moves”), when the camera moves, and when an object stops (it vanishes).

🇹🇭 กด Use my camera แล้วโบกมือ: เฉพาะขอบของสิ่งที่ขยับเป็นสี · ไม่มีกล้อง = คลิปถนน (ทุกเฟรมที่ 2 → ห่าง 83 ms) · ลาก τ ลง: noise ขึ้นทั้งภาพ · ลาก τ ขึ้น: เหลือแต่ขอบที่ชัด · ในคลิป τ 25: ราว 4% ของ pixel · ลองเปิดปิดไฟห้อง

C · Tracking

Follow a patch: template matching

Session 3, slide 7: slide, multiply, add. Here the “kernel” is a patch of the last frame (T3-2).
$$\text{NCC}=\frac{\sum (t-\bar t)(p-\bar p)}{\sqrt{\sum (t-\bar t)^2\,\sum (p-\bar p)^2}}$$
Worked example · brightness doubles

t = (1, 2, 3, 4), p = (2, 4, 6, 8) → deviations (−1.5, −0.5, 0.5, 1.5) and (−3, −1, 1, 3) → 10 ÷ √(5 × 20) = 1 — a perfect match

Next frame: found at (+30, −2) px, score 0.85. Keep the same patch and the score sinks to 0.37: legs move, the angle and background change.

C · Tracking

When IDs break

Fewer frames per second, faster objects or a stricter threshold → IoU drops → new IDs. Two people crossing → their boxes swap → ID switch.

Fixes: predict where each box moves before matching (Kalman filter, T9-4); remember what each person looks like — an embedding (session 5, slides 25 and 27).

Try it: link two frames

Try it
  1. Frame t: A (0, 0, 4, 4), B (10, 0, 14, 4). Frame t + 1: P (1, 0, 5, 4), Q (11, 1, 15, 5). Find IoU(A, P) and IoU(B, Q).

  3. Pixel values 80 → 70 and 80 → 120 with τ = 25: which pixel is “moving”?
Answer1. A–P: I = 3·4 = 12, U = 16 + 16 − 12 = 20 → 0.6 · B–Q: I = 3·3 = 9, U = 16 + 16 − 9 = 23 → 9/23 ≈ 0.39 · 2. at 0.3: A→P, B→Q · at 0.5: A→P only; Q gets a new ID and B is lost · 3. |70 − 80| = 10 → still · |120 − 80| = 40 > 25 → moving.

IoU = I ÷ (|A| + |B| − I)

link: highest IoU first, each box once, ≥ threshold

moving: |Iₜ − Iₜ₋₁| > τ

Session 9 · what to remember

What moved, where to, and what it all adds up to

  1. Optical flow: Iₓu + I_yv + Iₜ = 0 — one equation per pixel, so only the normal flow (the aperture problem).
  2. Lucas–Kanade: a window gives M (u, v)ᵀ = −(ΣIₓIₜ, ΣI_yIₜ)ᵀ — session 6's M; corners solve, edges slide; pyramids for big motion.
  3. Tracking: frame difference, template matching, or detect every frame and link boxes by IoU — IDs break with speed, low fps and crowds.
  4. Together: one pipeline from every session, a time budget measured stage by stage, and two or three solutions compared honestly.
