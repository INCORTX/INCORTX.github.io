Course Project

The project is 20 of the course’s 100 — proposal 10 + results, code & demo 10. It does not replace the final exam.

Who can do the project: students who handed in at least 5 of the 6 assignments (80%), each with all its files. The same rule decides who may sit the final.

Graded on experiment design, how you evaluate what you built, your analysis, and your ideas — not on how good the numbers are.

The task

Pick one real dataset (not a topic from the session notebooks), propose two or three solutions that take different routes, run every one, measure accuracy and speed / resources, and pick the best trade-off.

  • Your data, described and explored — what one row is, the columns, the files, the metadata, and an EDA.
  • Three or more core techniques your solutions are built on, from the course or the literature — each explained in your own words: theory, its role here, an example figure.
  • An experimental setting — how the data is split (train / validation / test) and what else every solution shares.
  • Accuracy — one metric that fits the task, the same for every solution, with a baseline beside it.
  • Speed / resources — time, memory or parameter count, as numbers.

Data ideas: data.go.th · UCI ML Repository · World Bank / Our World in Data · air quality, traffic or energy feeds · logs you are allowed to use · a survey or sensor log your group collects.

Rubric

Every criterion is marked on one scale — points = the item’s full points × the level:

100% Excellent75% Good50% Satisfactory25% Needs work0% Missing

Counted directly instead: C15 (complete sets of files) and P13 (on time).

Proposal — 10 points

30+ slides with page numbers · 20+ minutes · hand in clip + slides

  • P1Why this problem — where it comes from and what makes it hard · what the solution will output
  • P2Dataset & EDA — where it comes from and how it was collected · described in detail: what one row is, the columns, the files, the metadata · how many rows, and what is wrong with them · explored with EDA
  • P3Three or more core techniques — the techniques your solutions are built on, from the course or from the literature — every one explained in full, in your own words: the theory · what it does for this project · an example figure
  • P4Experimental setting — how the data is split (train / validation / test) and the other settings every solution shares — how you measure, seeds, the machine
  • P5Parameter study — every parameter and the value you plan to use · how changing each one would move the output
  • P6Two or three solutions — each with its workflow / pipeline / framework, plus pros and cons — two are required, a third is welcome
  • P7Creativity — an out-of-the-box idea, a strong concept, or a wide and interesting literature survey (any one)
  • P8Slides — 30+ pages · page numbers on every slide · at least one image · no slide over 6 lines
  • P9Slide design — attractive, engaging and easy to follow: clear figures and charts · a consistent layout and colour scheme · a storyline that holds attention
  • P10Length — 20+ minutes
  • P11Delivery — explained, not read off the slides · clear and fluent · well ordered, so listeners never get lost · easy to understand
  • P12Q&A — questions from the instructor and classmates
  • P13Submission — clip + slide deck, on time

Results, code & demo — 10 points

20+ slides with page numbers · 20+ minutes including a live run · hand in slides + .ipynb + clip

  • C1Accuracy — a metric that fits the task, and why · every solution measured with that metric on the same data · a baseline beside it
  • C2Speed / resources — training and prediction time, memory or parameter count for every solution — as numbers
  • C3Analysis per solution — what each solution got and why, from the numbers in C1 + C2
  • C4Experimental / parameter setting — the data split and experiment settings actually used, and the parameter values of each solution — and why you chose them
  • C5Overall analysis — the final choice with reasons on both axes · where the whole project breaks or is limited
  • C6Future work — what you would try next, and why
  • C7Creativity — an out-of-the-box idea, a strong concept, or a wide and interesting literature survey (any one)
  • C8Notebook + live demo — every experiment in one file that runs end to end · a live demo explaining every cell · cells chain into the full experiment for every solution, no dead cells · does not run = nothing for this item
  • C9Clean notebook — a section per solution with headings · meaningful variable / function names · no duplicated code
  • C10Slides — 20+ pages · page numbers on every slide · at least one image · no slide over 6 lines
  • C11Slide design — attractive, engaging and easy to follow: clear figures and charts · a consistent layout and colour scheme · a storyline that holds attention
  • C12Length — 20+ minutes including the demo
  • C13Delivery — explained, not read off the slides · clear and fluent · well ordered, so listeners never get lost · easy to understand
  • C14Q&A — questions from the instructor and classmates
  • C15Everything submitted — proposal clip + slide PDF, and results clip + slide PDF + notebook + data + README — each session counts only when all its files are in — files, on time

The same points for everyone in the group. Code that does not run scores nothing on C8.

Questions to prepare

Proposal and results — sample questions
Proposal
  • Why these core techniques, and where did each come from?
  • What really separates solution A from B? If they tie, which do you pick?
  • What about this dataset needs care before you use it?
Results
  • What does this cell do? What changes without it?
  • Why this max_depth / k / learning rate / number of epochs?
  • Which cell produced the number on this slide?
  • Double this parameter — which way does the result move, and why?
  • Why was the more accurate solution not the one you chose (or the other way round)?

AI and sources

AI may help write code, but you must understand every cell — the demo (C8) and Q&A (C14) check it. Cite any pretrained model, code or data you borrow on the slides and in the README; no citation counts as copying.
