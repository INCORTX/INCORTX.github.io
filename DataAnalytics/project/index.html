The project is 20 of the course’s 100: proposal 10 + results, code & demo 10. It does not replace the final exam. How the points split across the items below will be announced.

🎯 What the project is graded on: experiment design, how you evaluate what you built, your analysis, and your ideas and creativity — not on how good the numbers turn out. A solution that scores poorly but is compared well and explained is worth more than a pretty number nobody can trace.

01The task

Pick one real dataset, propose two or three solutions that take different routes, actually run every one of them, measure on both axes, and pick the best trade-off:

real data → EDA + preparation → solution A / B / C (tree-based · regression · clustering · neural network …) → accuracy + speed / resources → pick the best trade-off

Must have:

  • Four techniques in use — from the course or from the literature, but every one explained in full, in your own words: the theory · what it does for this project · an example figure (e.g. “median imputation because income is right-skewed”, not “because the sample code had it”)
  • Two or three solutions — each with its own workflow, plus pros and cons
  • Measured on two axes — accuracy (a metric that fits the task, the same one for every solution on the same data, with a baseline beside it) and speed / resources (time, memory or parameter count, as numbers)
  • Results need not be good — the points are for the idea, the comparison, and the analysis of why things came out the way they did

Data you can use — collect your own, or an open dataset: open government data (data.go.th) · the UCI Machine Learning Repository · World Bank / Our World in Data · air quality, traffic or energy feeds · sales or service logs you have permission to use · a survey or sensor log your group collects. Not one of the topics from the session notebooks.

C10Slides — 20+ pages · page numbers on every slide · at least one image · no slide over 6 lines

Group score — everyone in the group gets the same points, Q&A included; the instructor may ask anyone in the group, so everyone must understand the group’s code and results.
Running code is not a score — if it doesn’t run you can’t submit (does not run = nothing on C8). The points are for explaining what every cell does and reading your own results.

03Sample Q&A — prepare for these

Proposal session
  • Why these four techniques — and where did each one come from (which session, which paper)?
  • What really separates solution A from B? If they tie, which do you pick?
  • What about this dataset needs care before you use it?
Results session
  • What does this cell do? If you delete it, what changes?
  • Why this max_depth / k / learning rate / number of epochs?
  • Which cell produced the number on this slide?
  • Double this parameter — which way does the result move, and why?
  • Why wasn’t the more accurate solution the one you chose (or the other way round)?

05AI and attribution

You may use AI to help write code, but you must understand every cell you submit — the demo (C8) and the Q&A (C13) are where that is checked. If you use a pretrained model or borrow code or data, cite the source on the slides and in the README (no citation = treated as copying).
