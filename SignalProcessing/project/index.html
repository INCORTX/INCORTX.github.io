🎧 Digital Signal Processing · Session 0 › Project Brief

Course Project — 30 points

Replaces the final exam · same group as your presentation rounds (1–3 people) · proposal 14 (week 13) + results, code & demo 16 (week 14) · updated 2026-09-15

🎯 What the project is graded on: experiment design, how you evaluate what you built, your analysis, and your ideas and creativity — not on how good the numbers turn out. A solution that scores poorly but is compared well and explained is worth more than a pretty number nobody can trace.

1. The task

Pick one real signal set, propose two or three solutions that take different routes, actually run every one of them, measure on both axes, and pick the best trade-off:

real signal → load / sample → solution A / B / C (filter · spectral · feature …) → accuracy + speed / resources → pick the best trade-off

Must have:

  • Five techniques in use — from the course or from the literature, but every one explained in full, in your own words: the theory · what it does for this project · an example figure (e.g. “moving average because the noise is random around the true value”, not “because the sample code had it”)
  • Two or three solutions — each with its own workflow, plus pros and cons
  • Measured on two axes — accuracy (a metric that fits the task, the same one for every solution on the same data) and speed / resources (time, memory or parameter count, as numbers)
  • Results need not be good — the points are for the idea, the comparison, and the analysis of why things came out the way they did

Data you can use — record your own, or an open dataset: speech / music · ECG / EEG (PhysioNet) · phone sensors (accelerometer / gyro) · machine / motor vibration · hourly weather or energy data · seismic signals · minute-level stock / crypto prices

4. Sample Q&A (prepare for these)

Proposal session
  • Why these five techniques — and where did each one come from (which session, which paper)?
  • What really separates solution A from B? If they tie, which do you pick?
  • What about this dataset needs care before you use it?
Results session
  • What does this cell do? If you delete it, what changes?
  • Why this sample rate / window length / cutoff?
  • Which cell produced the number on this slide?
  • Double this parameter — which way does the result move, and why?
  • Why wasn't the more accurate solution the one you chose (or the other way round)?

6. AI and attribution

You may use AI to help write code, but you must understand every cell you submit — the demo (C7) and the Q&A (C11) are where that is checked. If you use a pretrained model or borrow code or data, cite the source on the slides and in the README (no citation = treated as copying).
