/ˈkɔː.zəl/

อ่านว่า “เดลตา เอ็น” · สัญญาณที่มีค่า 1 ที่ n=0 และเป็น 0 ทุกที่อื่น (เคาะครั้งเดียวสั้นที่สุด)

A · Systems & LTI A system is a box: input → output
y[n] = T{ x[n] }

T{·} is an operator — it maps the whole signal in to the whole signal out, not one sample at a time.

1

Every filter, effect, and neural layer is just a system.

2

The operations from Session 1 — scale, shift, add — are each a system.

⚠️

y[n] = T{x[n]} doesn't mean y[n] depends only on x[n] — an echo y[n] = x[n] + 0.5·x[n−1] uses x[n−1] too.

1 /
A · Systems & LTI Linearity — two conditions
✅

Linear = scaling and adding pass straight through.

Turn the volume up 2× and the output is exactly 2× louder. Add two sounds and the outputs add too.

1 /
A · Systems & LTI Time-invariance & causality
Time-invariant

the rule never changes with time

Causal

output uses only past & present

⚠️

Time-invariance ≠ causality. The shift k can point either way (even toward x[n+1]); whether the system uses a future sample is causality. y[n] = x[n+1] is time-invariant but non-causal.

🔑

LTI = Linear + Time-Invariant — the class of systems we can analyse with convolution. Causal is a separate, optional property — an LTI system may be non-causal (e.g. y[n]=x[n+1]). We'll assume LTI from now on.

1 /
A · Systems & LTI 🎯 Why does LTI matter so much?
🔑

An impulse δ[n] (read “delta of n”) is 1 at n = 0 and 0 everywhere else — the shortest possible tap.
… 0  0  1  0  0 …

Example: one clap in a hall ≈ δ[n]. The echo that comes back is that hall's h[n] — one clap measures the whole room.

If a system is LTI, knowing its response to ONE impulse predicts its response to ANY signal.

🦸

That is the superpower we unlock with convolution — adding up all the shifted echoes (built in sub-topic B).

1 /
A · Systems & LTI 🔍 Linear? Both routes must agree
🔑

Linear = the two routes always meet. Scaling and the system can be done in either order and still land on the same answer.

Here they don't: squaring turns a ×2 at the input into a ×4 at the output, so the top route overshoots. y[n] = x[n]² is not linear.

🔁

Time-invariance is the same picture — just swap ×2 for shift by k: shift-then-system must equal system-then-shift.

1 /
A · Systems & LTI 🌍 Concert halls are LTI
👏 clap = δ[n]  →  🎙️ recording = h[n]  →  any sound = x[n] ∗ h[n]
🎚️

The hall is the system T{ } — clap δ[n] in, echo h[n] out. It is (approximately) LTI, so any sound x[n] comes back as x[n] ∗ h[n]: record one clap, then simulate the hall on a laptop — never setting foot in it. One clap really does describe the whole room. — Photo: Sumida Triphony Hall, Tokyo · public domain (U.S. Navy, Wikimedia Commons).

1 /
A · Systems & LTI 🔍 How do you know a real system is LTI?
🧱

The shortcut is the one you will actually use. y[n] = x[n] − x[n−1] is a delay and a subtract → LTI by inspection. y[n] = n·x[n] scales by n, not a constant → shortcut refused, and the test confirms it breaks.

⚠️

Almost nothing real is exactly LTI. That is what "a hall is approximately LTI" meant: LTI until you shout loud enough to distort the air — like an amplifier, linear until it clips.

Engineering runs on "LTI enough, over the range we use it".

A · Systems & LTI
💻 LAB — Test a System
①The system: y[n] = x[n] − x[n−1]
②Check linearity (scale + add) AND time-invariance
③Then test a new system yourself
lab.py
import numpy as np
def sys(x): return np.diff(x, prepend=0)   # y[n] = x[n] − x[n−1]
x1 = np.array([1,3,2,5]); x2 = np.array([4,0,1,2])
print(sys(2*x1), 2*sys(x1))   # scaling warm-up
⚙️

An LTI system is linear (scaling + adding carries through) and time-invariant.

1 /
A · Systems & LTI 🔍 Explore — Full LTI Check

A real check tests BOTH conditions — linearity (scale + add) and time-invariance.

explore.py
shift = lambda v: np.concatenate([[0], v[:-1]])   # delay by 1
a, b = 2, 3   # reuse sys, x1, x2 from the setup slide
# np.allclose = "are these equal?", allowing for float rounding
lin = np.allclose(sys(a*x1 + b*x2), a*sys(x1) + b*sys(x2))
ti  = np.allclose(sys(shift(x1)), shift(sys(x1)))
print("linear:", lin, "· time-invariant:", ti)
🔎

Output: linear: True · time-invariant: True → both hold, so the difference system is LTI.

1 /
A · Systems & LTI 🎯 Your Turn — Predict, Then Verify
🎯

Predict first: is y[n] = n·x[n] (multiply by the index n) an LTI system?

yt.py
def sysB(x): return np.arange(len(x)) * x   # y[n] = n·x[n]
lin = np.allclose(sysB(a*x1 + b*x2), a*sysB(x1) + b*sysB(x2))
ti  = np.allclose(sysB(shift(x1)), shift(sysB(x1)))
print("linear:", lin, "· time-invariant:", ti)
✅

Output: linear: True · time-invariant: False → linear but NOT time-invariant (×n changes with time) → not LTI. (×constant is fine, ×n is not.)

B · Impulse Response & Convolution Key Terms — Convolution

Impulse response h[n]

/ˈɪm.pʌls rɪˈspɒns/

The output when the input is a single unit impulse.

output เมื่อ input เป็น impulse

Convolution — written x ∗ h

/ˌkɒn.vəˈluː.ʃən/

Combine x and h to produce the output y. The ∗ is not multiplication — the length gives it away: [1,2] ∗ [1,1] = [1,3,2] (three taps), while multiplying would give [1,2] (two).

รวม x กับ h ได้ output · ∗ ไม่ใช่การคูณ — ดูความยาวก็รู้: convolve แล้วยาวขึ้น คูณแล้วเท่าเดิม

Flip

/flɪp/

Reverse one sequence in time.

พลิกลำดับกลับด้านเวลา

Slide (shift)

/slaɪd/

Move the flipped sequence one step at a time.

เลื่อนลำดับที่พลิกทีละขั้น

1 /
B · Impulse Response & Convolution Impulse response = the fingerprint
🔑

Know h[n], and you can predict the output for ANY input.

So where do you get h? Clapping measures it — one clap describes the whole system.

✏️

Or don't measure. h is the output for δ — so if you know the rule, just put δ in for x:

feed x = δ = [1, 0, 0]  ← ONE impulse, not [1, 1, 1]
y[n] = x[n] + 0.5x[n−1] + 0.25x[n−2]  ← the rule
h[n] = δ[n] + 0.5δ[n−1] + 0.25δ[n−2]  ← swap x → δ
δ[n]   = [1, 0, 0]
δ[n−1] = [0, 1, 0]  ← each delay picks its slot
δ[n−2] = [0, 0, 1]
h       = [1, 0.5, 0.25]  ← same as measured
1 /
B · Impulse Response & Convolution Why the output is a convolution
🔑

Three roles, and two of them are outputs.
x — the input we feed.
h — the output the system gave to one known input, δ.
y — the output for our x. This is what we want.

Why we have no choice. We know x — it is ours. What we do not know is the system, and h is all we get. So we rebuild x out of impulses and let LTI carry each piece through.

➕

That rebuild-and-add is convolution: it turns the answer for δ into the answer for x. y = x ∗ h

1 /
B · Impulse Response & Convolution The convolution formula
🧭

Don't memorize the sum — remember the 4 steps.

Flip → Shift → Multiply → Sum
🔗

"Overlapping" = line the flipped h up against x; only the samples that land on top of each other get multiplied. Slide h along and the overlap changes — that is why y[n] changes with n.

We'll slide it step by step on the next slides.

1 /
B · Impulse Response & Convolution Reading the indices — fix n, sweep k
📌

n is the output you fix. Here n = 3 — you build one number, y[3]. A different n slides h elsewhere.

🔁

k is the running index you sweep, then sum away. It visits every input x[k], weighted by h[n−k]. Only the k whose n−k lands inside h contribute — “sum over overlapping k”.

🔑

h vs y — same box, different input. Feed δ → out comes h (the fixed fingerprint); feed x → out comes y. h is just y for the special input δ.

1 /
B · Impulse Response & Convolution Step by step — Flip, Shift, Multiply, Sum

① Flip h = [2,1] → [1,2]. ② Slide it along x, ③ multiply the overlapping cells, ④ add:

y[0]1·2 = 2
y[1]1·1 + 2·2 = 5
y[2]2·1 + 3·2 = 8
y[3]3·1 = 3
y = [2, 5, 8, 3]
🔄

Why flip? Fixing output n, the sample that just arrived meets h[0] and older ones meet later h — so under x, h reads backwards. It falls out of h[n−k], not a rule to memorise.

1 /
B · Impulse Response & Convolution Try it: slide the kernel

Position n = 0

Each press slides the flipped kernel one step, multiplies the overlapping cells, and drops the sum into y.

1 /
B · Impulse Response & Convolution Flip or no flip? Two routes, one answer
📤

Reach for SCATTER (no flip) when you want all of y at once, or you picture "each impulse fires an echo." The whole-array code is one line — y[k:k+M] += x[k]*h — and it never flips.

🎯

Reach for GATHER (flip) when you want a single y[n], or you are following the formula y[n] = Σ x[k]·h[n−k] by hand. The flip is exactly what h[n−k] demands.

1 /
B · Impulse Response & Convolution How long is the output?
len(y) = len(x) + len(h) − 1
✅

A quick self-check: the output is always longer than either input. Wrong count → you slipped.

1 /
B · Impulse Response & Convolution 🌍 The same operation runs in every CNN (Convolutional Neural Network)
∗
🤖

These are real convolutions. Slide a small kernel over the photo, multiply-and-sum at every pixel — a box kernel blurs, a Sobel kernel finds edges. The same flip-shift-multiply-sum runs in every CNN layer: 1-D here → 2-D on images. This session's skill feeds AI directly. — Photo “Brick building with glass windows”, public domain (Wikimedia Commons); blur & edges computed by 2-D convolution.

B · Impulse Response
💻 LAB — Convolve with h[n]
①The same x and h we just walked on the board
②Let NumPy do it — does it match our hand answer?
③Then build it yourself, both ways
lab.py
import numpy as np
x = np.array([1, 2, 3])   # the same x as the slides
h = np.array([2, 1])      # the same h — asymmetric, so the flip is real
print(np.convolve(x, h))
💥

Output: [2 5 8 3] — the same four numbers we got by hand. NumPy is not doing anything magic; it is doing what you just did.

1 /
B · Impulse Response 🔍 Explore — Both Ways, One Answer
explore.py
N = len(x) + len(h) - 1
# A — walk k, drop a FORWARD copy of h at each. no flip.
yA = np.zeros(N, int)
for k in range(len(x)):
    yA[k:k+len(h)] += x[k] * h
# B — fix n, reach back through a FLIPPED h
yB = np.array([sum(x[k]*h[n-k] for k in range(len(x))
               if 0 <= n-k < len(h)) for n in range(N)])
print(yA, yB, np.array_equal(yA, yB))
🔎

Output: [2 5 8 3] [2 5 8 3] True
A never flips. B does. They agree. Flipping is not a property of the problem — it is what you owe h[n−k] when you fix n and reach backwards.

C Sub-topic C · Step Response & Running-Sum
🌍 In the real world

Flip a switch ON and hold it. Why does the output ramp up gradually instead of jumping?

🔄

Why not the hall this time? A step means hold the input on forever — and a held-constant sound is just DC: you cannot hear it, and a speaker cannot even make it. The hall was perfect for one clap and is useless for a switch left on. Same LTI system, new question — so we need something you can genuinely leave on.

1 /
C · Step Response Key Terms — Step Response

Unit step u[n]

/ˈjuː.nɪt stɛp/

An input that is 0 before n = 0, then stays 1 forever after.

input ที่เป็น 0 ก่อน n=0 แล้วเป็น 1 ตลอด

Step response s[n]

/stɛp rɪˈspɒns/

The output when the input is a unit step.

output เมื่อ input เป็น unit step

Running / cumulative sum

/ˈrʌn.ɪŋ ˈkjuː.mjə.lə.tɪv sʌm/

Add up the values one position at a time.

บวกสะสมค่าทีละตำแหน่ง

1 /
C · Step Response Feed a unit step into an LTI system
🔗

Step response is just a convolution: s[n] = u[n] ∗ h[n]. Same machinery as an impulse — only the input changed from one tap to a held-on switch.

🔦

Because u is all 1s, every tap of the step fires the same h, and the sum collapses to a running total of h — worked out on the next slides.

1 /
C · Step Response Step response = running sum of h[n]
➕

Convolving with a step = accumulating the impulse response.

🟰

These are the same formula, not two. The top says what s[n] is; the bottom says how to get it. Both give s[2] = 6 — the top adds three numbers, the bottom adds two.

⚠️

Use the bottom one. Re-adding all of h at every step is the classic slip — and it costs N²/2 additions instead of N. np.cumsum is exactly the bottom line.

1 /
C · Step Response 🔍 Why it is an accumulation
🧱

Hold a step on and you keep tapping — one impulse at every time: u = δ[n]+δ[n−1]+δ[n−2]+…

🔁

LTI fires the same h for each tap, just shifted (one row above). By time n the copies stack, so column n holds h[0]+…+h[n] — that is the running sum.

💡

Impulse and step response are two views of one system — reaction to a single tap versus a switch held on.

1 /
C · Step Response ↩ Back to the heater
🔥

The gradual rise is the running sum of h[n]. It flattens once h has fully played out — and note the heater is still ON. It has hit equilibrium: heat going in now equals heat leaking out. Switch it off and the curve falls instead of flattening — staying flat is the proof it is still running.

1 /
C · Step Response 🔍 Explore — Is It Really the Running Sum?
explore.py
step = np.ones(5, int)              # an input actually held at 1 forever
s_conv = np.convolve(h, step)[:5]   # feed the step in for real
s_cum  = np.cumsum(h)                # just add h up
print(s_conv, s_cum, np.array_equal(s_conv[:len(h)], s_cum))
🔎

Output: [1 3 6 6 6] [1 3 6] True — feeding a real step and merely accumulating h give the same numbers. It climbs while h still has values to give, then flattens at sum(h) = 6 — output settles when h runs out, not when the input stops.

D · Correlation Key Terms — Correlation

Correlation

/ˌkɒr.əˈleɪ.ʃən/

A measure of similarity found by sliding one signal past another.

วัดความคล้ายด้วยการเลื่อน

Cross-correlation

/krɒs ˌkɒr.əˈleɪ.ʃən/

Similarity between two different signals.

ความคล้ายระหว่างสองสัญญาณ

Lag

/læɡ/

How far you slide one signal before multiplying and summing. Lag 0 = no shift.

จำนวนช่องที่เลื่อนก่อนคูณแล้วบวก · lag 0 = ไม่เลื่อน

Auto-correlation

/ˈɔː.təʊ ˌkɒr.əˈleɪ.ʃən/

A signal compared with a shifted copy of itself.

สัญญาณเทียบกับตัวเอง

1 /
D · Correlation Correlation = convolution without the flip
Convolution

the flip is the only difference

Correlation

same machinery, one difference

🔁

If you can convolve, you can correlate — just skip the flip.

1 /
D · Correlation Template matching
🏷️

Template matching IS cross-correlation. The "two different signals" from the definition are your signal and the template — one operation, two names.

📍

Slide the template across the signal; where they line up, the multiply-and-sum spikes. Peak = best match location.

1 /
D · Correlation Cross-correlation matches two different signals
🔀

Two different signals — that is the "cross", and there is no flip. The peak is the answer: lag 1 = 5 — because x[1:3] = [2, 1] is g exactly. Lag 0 overlaps the same two samples yet scores only 4, so the peak found the shape, not just the overlap.

✂️

At lag 2, g's second tap ran off the end — no partner, nothing to multiply. That is the only way a term vanishes: correlation never asks whether numbers are equal, it multiplies whatever shares a slot.

1 /
D · Correlation Auto-correlation finds a repeating period
⚠️

There is no template here. Template matching slides a different signal over yours; auto-correlation slides the signal over itself — so what you seek is always in there, perfectly, at lag 0.

💓

That is why lag 0 always wins: every sample multiplies itself — 1²+3²+… — and squares never cancel, so no shift can beat it. Which means lag 0 tells you nothing. Read the biggest peak after it: lag 4 = 20, one period on — that is how a machine reads pitch, or a heartbeat rate.

1 /
D · Correlation 🌍 GPS & Wi-Fi find delay by correlation
🛰️

The peak lands at lag 5 — where the late code begins. Height 8 = Σ(value²) (same rule as lag 0 = 30); ±1 makes it equal the chip count since (+1)(+1) and (−1)(−1) both give +1. Delay × speed of light = distance.

🧩

Read the height as confidence: each corrupted chip flips a +1 to −1, so the peak drops by 2 — 8 = flawless, 0 = unreadable. GPS designs its code to beat neighbours: this 8-chip 2×, a 31-chip random ~3.4×, all-1s only 1.1×.

1 /
D · Correlation
💻 LAB — Cross-Correlate
①Two sequences, x and a template g
②np.correlate slides one past the other
③The peak marks the best alignment
lab.py
import numpy as np
x = np.array([1, 2, 1]); g = np.array([2, 1])
c = np.correlate(x, g, "full")
print(c, "lag =", c.argmax() - (len(g) - 1))
💥

Output: [1 4 5 2] lag = 1 — the same peak we drew by hand, and x[1:3] = [2, 1] really is g, so the peak is 2²+1² = 5. "full" also counts g hanging off the left, so subtract len(g)−1 to get the lag.

1 /
D · Correlation 🔍 Explore — Correlation Is Convolution Without the Flip
explore.py
# correlation, straight from the library
a = np.correlate(x, g, "full")
# convolution — but hand it g ALREADY reversed
b = np.convolve(x, g[::-1])
print(a, b, np.array_equal(a, b))
🔎

Output: [1 4 5 2] [1 4 5 2] True — they are the same operation. Convolution flips h for you; correlation does not. So correlation is convolution fed a pre-flipped kernel — the only difference between them is that flip.

E Sub-topic E · Convolution Algebra
🌍 In the real world

A guitar rig chains EQ → reverb, and splits into dry + wet that add back. Can the whole rack become ONE filter h[n] — and does order matter?

🎯

Three algebra rules do it. Commutative, associative & distributive collapse any chain of filters into a single h[n] — computed once, then one convolution per sample, not three. Series is ∗, parallel is +.

🎛️

Never touched a pedalboard? An EQ shapes bass/treble; a reverb adds a room's echo. Dry = untouched guitar, wet = effected copy. Each pedal is just an LTI system with its own h[n].

E · Convolution Algebra Key Terms — Convolution Algebra

Commutative

/kəˈmjuː.tə.tɪv/

Order doesn't matter: x∗h = h∗x.

สลับที่ได้

Associative

/əˈsəʊ.ʃə.tɪv/

Grouping doesn't matter: (x∗h₁)∗h₂ = x∗(h₁∗h₂).

จัดกลุ่มได้

Distributive

/dɪˈstrɪb.jə.tɪv/

Spreads over addition: x∗(h₁+h₂) = x∗h₁ + x∗h₂.

กระจายได้

Filter

/ˈfɪl.tər/

An LTI system used to shape a signal — its h[n] is the filter (the box from sub-topic A).

ระบบ LTI ที่ใช้แต่งสัญญาณ · h[n] คือ filter

Series (cascade)

/ˈsɪə.riːz/

Filters in a row — combine by convolving (∗).

ต่อเรียงกัน · รวมด้วย convolve (∗)

Parallel

/ˈpær.ə.lel/

One input, outputs added — combine by adding (+).

ป้อนเข้าหลายตัวแล้วบวก (+)

E · Convolution Algebra Three properties, in plain terms
🧰

These let us simplify filter chains — reorder, merge, or split them.

The same three rules you know from ordinary multiplication and addition.

E · Convolution Algebra δ[n] is the "1" of convolution
1️⃣

Convolving with δ leaves a signal unchanged — like multiplying a number by 1.

This is exactly why h[n] (the response to δ) describes the whole system.

1 /
E · Convolution Algebra 🔍 Why convolution commutes
🔄

Which one you flip doesn't matter — the overlap is identical.

A change of index variable, not a heavy proof, shows x∗h = h∗x.

1 /
E · Convolution Algebra 🌍 Combine filters in a pipeline
⚡

Audio and image pipelines combine many filters into one for speed. Associativity makes this valid.

1 /
E · Convolution Algebra Series → convolve the responses
Series → h = h₁ ∗ h₂

Output of h₁ flows into h₂. Merge them into one impulse response by convolving.

1 /
E · Convolution Algebra Parallel → add the responses
Parallel → h = h₁ + h₂

One input feeds both systems; the outputs add. Merge by adding the responses (distributivity).

1 /
E · Convolution Algebra Reduce a block diagram inside-out
🧩

Like clearing brackets in an equation: innermost first. Here the series h₁∗h₂ sits inside a parallel branch, so it collapses before the branches add.

⚠️

There is no "always + first" rule. The order follows the nesting, not the operator — reach for whatever is deepest.

1 /
E · Convolution Algebra ↩ Back to the pedalboard
🎸

The whole rack = one h[n]: convolve the series parts, add the parallel parts. The ∗ is not multiplication. Take h₁ = [1, 2] and h₂ = [1, 1]: series gives h₁ ∗ h₂ = [1, 3, 2] — three taps; parallel gives h₁ + h₂ = [2, 3] — two. Multiplying would give [1, 2]. Convolving lengthens, multiplying does not — that alone proves they are different operations.

E · Convolution Algebra
💻 LAB — Commutativity
①Two filters, x = [1, 2] and h1 = [3, 1]
②Convolve them both ways round
③Same answer either way?
lab.py
import numpy as np
x = np.array([1, 2]); h1 = np.array([3, 1]); h2 = np.array([1, 1])
print(np.convolve(x, h1), np.convolve(h1, x))
💥

Output: [3 7 2] [3 7 2] — x ∗ h1 = h1 ∗ x. Which one you call 'the signal' and which 'the filter' makes no difference — so a chain reorders freely.

1 /
E · Convolution Algebra 🔍 Explore — Series Convolves, Parallel Adds
explore.py
# ASSOCIATIVE → a series cascade becomes ONE filter
left  = np.convolve(np.convolve(x, h1), h2)   # through h1, then h2
right = np.convolve(x, np.convolve(h1, h2))   # or the merged filter h1∗h2
print(left, right, np.array_equal(left, right), "| merged:", np.convolve(h1, h2))
# DISTRIBUTIVE → a parallel pair becomes ONE filter
print(np.convolve(x, h1 + h2), np.convolve(x, h1) + np.convolve(x, h2))
🔎

[3 10 9 2] [3 10 9 2] True | merged: [3 4 1], then [4 10 4] [4 10 4]. Associativity is why a series cascade collapses to one filter h1∗h2; distributivity is why a parallel pair adds. Series ∗, parallel +.

✎Checkpoint — LTI Properties⏱ 3 min

A system computes y[n] = 3·x[n]. Is it (a) linear? (b) time-invariant?

A) Both
B) Linear only
C) Time-invariant only
D) Neither
1 /
✔Answer — LTI Properties
A) Both

Scaling by a constant is linear; the rule never changes with time → time-invariant.

❌ Common mistake: assuming any multiplication breaks linearity. Multiplying by a constant is fine; multiplying by n (e.g. y[n]=n·x[n]) is not — that one is not time-invariant.

Which system is NOT causal (uses a future input)?

B) y[n] = x[n+1]
C) y[n] = 2·x[n]
D) y[n] = x[n−2]
1 /
✔Answer — Causality
B) y[n] = x[n+1]

x[n+1] is a future sample — a real-time system can't see it yet.

❌ Common mistake: thinking x[n−2] is non-causal. A delay looks "backward" (into the past), which is perfectly causal. Future = index bigger than n.
