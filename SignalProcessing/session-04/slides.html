A · Convolution Recap Convolution in four steps
🔁

Repeat steps 2–4 for every n — one output value per shift.

🎯

Run these four steps as a system and you never miss an index or a sign.

1 / 89
🧮Worked Example — convolution two ways: flip vs no-flip

x = [1, 2, 3]  ∗  h = [1, 2]  →  y = [1, 4, 7, 6]

① Flip & slide gather — y[n] = Σ x[k]·h[n−k]
flip h → [2, 1], slide it across x
y[0]1·1 = 1
y[1]1·2 + 2·1 = 4
y[2]2·2 + 3·1 = 7
y[3]3·2 = 6
✅ reads off any single y[n] directly · matches the formula
❌ must flip h & track n−k → the #1 sign / index slip
▶ Use when: you need one / a few outputs, real-time streaming, or a quick exam hand-calc.
② No-flip · distribute scatter — each x[k] fires h
write x[k]·h shifted to k, add columns
x[0]=11·[1,2] → [1, 2, 0, 0]
x[1]=22·[1,2] → [0, 2, 4, 0]
x[2]=33·[1,2] → [0, 0, 3, 6]
add ↓[1, 4, 7, 6]
✅ no flipping → fewer sign errors · pure superposition
❌ builds the whole output at once · more rows to add
▶ Use when: you want the whole output at once, short sequences by hand, or the superposition / LTI view.
Both give y = [1, 4, 7, 6] — same convolution, two ways of bookkeeping

A · Convolution Recap See it slide: where the overlaps are

Flip h → [2, 1], then slide it one step at a time under x = [1, 2, 3]. Only the shaded overlap is multiplied & summed — no need to picture it in your head.

1 /
A · Convolution Recap See it distribute: no flip, add the columns

The other way — no flipping. Multiply each input value x[k] by the whole kernel h = [1, 2] → a scaled copy of h. The index k is not multiplied — it only says which column the copy starts at (the shift). Then add each column.

1 /
A · Convolution Recap 🌍 The same convolution runs inside every CNN (Convolutional Neural Network)
🧠

The convolution you did by hand is what a CNN does on images — one more dimension. That kernel is h: a CNN learns h from data, in DSP you design it — same math, x ∗ h = y.

🔑

h is the system, not the output of x. h = the response to a single impulse δ (its fixed fingerprint); your real signal x gives the output y = x ∗ h.

1 /
A · Convolution Recap δ ∗ h = h — why one clap gives you h

Feed the system a single impulse δ = [1, 0, 0, …] and the output is h itself — δ is convolution's "1", so it returns h unchanged (like ×1).

👏

Clap (≈ δ) → echo = δ ∗ h = h. The echo is an output (y), but this special y equals h because the input was an impulse.

🎵

Music (any x) → y = x ∗ h ≠ h. A normal input gives a normal output — only an impulse input hands you h directly.

A · Convolution Review 🎯 Your Turn — Build Convolution Yourself
🎯

Predict on paper (x = [2, 1, 3], h = [1, 1], length 4), then build convolution yourself with the distribute method from page 8 — no np.convolve in the loop.

yt.py
import numpy as np
x = [2, 1, 3];  h = [1, 1]
y = [0] * (len(x) + len(h) - 1)          # a zero-filled list of length N+M−1 to add into
for k in range(len(x)):                    # each input sample x[k]…
    for j in range(len(h)):                # …adds a scaled, shifted copy of h
        y[k+j] += x[k] * h[j]
print(y)                                 # your own convolution
print(np.convolve(x, h))                 # must match the library
✅

Expected [2, 3, 4, 3]. Both prints match — you re-created np.convolve in three lines. That inner loop is the distribute method.

B · Moving Average Key Terms — Moving Average (box & weighted)

Moving average

/ˈmuː.vɪŋ ˈæv.rɪdʒ/

The average of a window of samples that slides along the signal.

เฉลี่ยค่าในหน้าต่างที่เลื่อนไป

Weighted MA

/ˈweɪ.tɪd/

An average that uses unequal weights across the window.

เฉลี่ยด้วยน้ำหนักไม่เท่ากัน

Window size (N)

/ˈwɪn.doʊ saɪz/

How many samples are averaged together.

จำนวนค่าที่นำมาเฉลี่ย

Weight (wₖ)

/weɪt/

Each filter coefficient (one per tap). wₖ = the weight at position k (w₀, w₁, w₂, …). A flat box uses wₖ = 1/N.

น้ำหนักแต่ละตัว (1 ต่อ tap) · wₖ = น้ำหนักที่ตำแหน่ง k · box แบน = 1/N

Smoothing

/ˈsmuː.ðɪŋ/

ลดการแกว่งเร็ว ให้เห็นแนวโน้ม

Normalization

/ˌnɔːr.mə.lɪˈzeɪ.ʃən/

Choosing weights that sum to 1 so the level is preserved.

ทำให้ผลรวม weight = 1

Triangular weights

/traɪˈæŋ.ɡjə.lər/

Center weighted more, e.g. {¼, ½, ¼}.

เน้นค่ากลาง เช่น {¼,½,¼}

B · Moving Average Moving average is convolution
h = [1/N, …, 1/N]
1

Averaging the last N samples is convolution with a flat kernel.

✅

Not a new operation — the same flip-shift-multiply-sum, just with equal weights.

1 / 89
B · Moving Average The window slides one sample at a time
🪟

Each window position produces one output value. Slide the window across the whole signal and you get the smoothed line — that's the "moving" in moving average.

1 / 89
B · Moving Average 🔍 Why does averaging smooth the line?

Averaging neighbours cancels the fast random jitter (it swings up and down), but keeps the slow trend (it stays put).

📉

This is your first lowpass filter: it passes slow changes and blocks fast ones.

1 / 89
B · Moving Average Why divide by N? To keep the level

The DC gain is just the sum of the weights (Σₖ h[k]). Dividing by N makes that sum 1, so a constant passes through unchanged — DC gain = 1.

DC = Direct Current — a constant signal. DC gain = how much a constant input is scaled up or down.

⚠️

Without the ÷N the level would scale up. Smoothing must never shift the average level.

1 / 89
B · Moving Average Try it: drag the window size

delay ≈ (N−1)/2 = 2 samples

= how many samples the smooth line lags behind the signal (the window's centre sits that far back). Bigger N → more lag.

Small N follows the signal closely (little smoothing). Large N is very smooth but lags and flattens the peaks.

before — bars drawn equal: the signal has all frequencies about equally
after MA — how much of each frequency is left

The moving average passes low frequencies (slow trends) and shrinks high ones (fast jitter) — each frequency gets a different gain.

Fast wiggle [5,0,5,0,…] → MA÷3 → [3.33, 1.67, …]
level (DC): 2.5 → 2.5 ✓ kept  ·  swing: ±2.5 → ±0.83 (÷3)

constant = 0 Hz → kept · fast jitter = high Hz → reduced. A flat [5,5,5,5] is pure DC — nothing to remove.

B · Moving Average Weighted MA — the general formula

Give each sample in the window its own weight — the weights must sum to 1:

with   w₀ + w₁ + w₂ = 1

🧮 Example — w = {¼, ½, ¼}, window x = [8, 12, 8]
y = ¼·8 + ½·12 + ¼·8 = 2 + 6 + 2 = 10
the centre (12) counts most → the peak is kept · a flat box {⅓,⅓,⅓} would give (8+12+8)/3 = 9.33
🎚️

Same window — just redistribute the weights. Flat MA is simply wₖ = 1/N.

1 /
B · Moving Average Still convolution — only the shape of h changes
Flat MA — h = [⅓, ⅓, ⅓]

a rectangle

Triangular — h = [¼, ½, ¼]

a peak in the middle

🔑

Weighted MA is still convolution — h just isn't flat. Change the shape of h[n] and you change the filter. This is the key to FIR (Session 8).

1 / 89
B · Moving Average 🔍 Why weighting the center preserves a peak

A flat average spreads weight evenly, so it crushes sharp peaks. Weighting the center keeps the peak taller while still smoothing the noise.

🏔️

That's why real signal processing often prefers weighted over flat averages.

B · Moving Average
💻 LAB · Run — Smooth: box vs weighted

Two moving averages on the same signal — a flat box and a centre-weighted kernel. Only the shape of h differs.

lab.py
import numpy as np
x = np.array([4, 8, 6, 2, 10, 4])
box = np.convolve(x, np.ones(3)/3,     "valid")   # flat MA(3)
tri = np.convolve(x, [0.25, 0.5, 0.25], "valid")   # weighted (triangular)
print("box:", box.round(2))     # [6.   5.33 6.   5.33]
print("tri:", tri.round(2))     # [6.5  5.5  5.   6.5 ]
⚖️

Both smooth the signal — the weights just change the shape of h. Flat = every neighbour equal; triangular = the centre sample counts most.

B · Moving Average 🎯 Your Turn — Build a Weighted MA Yourself
🎯

Predict on paper (x = [4, 8, 12, 8, 4], w = [¼, ½, ¼]), then build the weighted MA yourself — a sliding weighted sum, no np.convolve in the loop.

yt.py
import numpy as np
x = [4, 8, 12, 8, 4];  w = [0.25, 0.5, 0.25]      # weights sum to 1
y = []
for n in range(len(x) - len(w) + 1):       # each full window…
    y.append(sum(w[k]*x[n+k] for k in range(len(w))))   # …weighted sum
print(y)                                  # your weighted MA
print(np.convolve(x, w, "valid"))          # must match (w symmetric)
✅

Expected [8, 10, 8]. Triangular keeps the peak at 10; a flat box MA(3) would drop it to 9.33. Choosing the weights = designing the filter → FIR, Session 8.

def moving_average(x, N):
    y = [sum(x[i:i+N]) / N for i in range(len(x) - N + 1)]   # ← you write this
    return y, len(y), (N - 1) / 2

x = [4, 8, 6, 2, 10, 5, 7, 3, 9, 6]

D · Real-time & Causality Causal vs centered moving average
Causal (real-time)

y[n] = (x[n]+x[n−1]+x[n−2]) / 3

Centered (needs future)

y[n] = (x[n−1]+x[n]+x[n+1]) / 3

⏳

Live / streaming → must be causal. x[n+1] hasn't arrived yet, so a centered window is impossible in real time.

✅

Recorded / offline data → centered is fine. The whole signal is already stored, so x[n+1] exists — centered MA is common in analysis (near-zero delay).

1 / 89
D · Real-time & Causality Running sum: add the newest, drop the oldest

Keep a rolling total S — each step is just one add + one subtract, not re-summing all N.

Example — window [3, 9, 6] → [9, 6, 12]:
old  S = 3+9+6 = 18  →  y = 18/3 = 6
new S = 18 − 3 + 12 = 27  →  y = 27/3 = 9
⚡

Then y[n] = S[n] / N: S is a running sum → ÷N turns it into the average. Cost is O(1) per sample, no matter how big N is.

1 / 89
D · Real-time & Causality 🔍 Latency — the price of real-time smoothing

A causal MA only looks back, so it reacts late — the output reaches the half level about (N−1)/2 samples after the step, and the sharp edge becomes a gentle ramp.

Bigger N → smoother, but more delay (same trade-off as Sub-topic C).
⏱️

Centered MA has near-zero delay but is not causal. Real-time work trades a little latency for less noise.

1 / 89
D · Real-time & Causality 🌍 ECG monitors & game controllers
💓

ECG monitors smooth each sample as it arrives (causal); game controllers use a tiny causal window to stay responsive. The running sum keeps CPU cost flat even at high sample rates.

D · Real-time & Causality
💻 LAB · Run — Build a Causal Running-Sum MA

Smooth in real time using only current + past samples — one add, one subtract per step (O(1)).

lab.py
import numpy as np
x = [4, 8, 6, 2, 10, 5];  N = 3
S = 0; y = []
for n in range(len(x)):
    S += x[n]                      # add the newest
    if n >= N: S -= x[n-N]         # drop the one that left
    if n >= N-1: y.append(S/N)     # output once the window is full
print([round(v,2) for v in y])                         # [6, 5.33, 6, 5.67]
print(np.convolve(x, np.ones(N)/N, "valid").round(2))   # same result
⚡

Same answer as np.convolve, but the running sum costs O(1) per sample whatever N is — and it's causal (past-only), so it lags by (N−1)/2.

E · FIR Filter What is an FIR filter?

FIR = Finite Impulse Response — a filter you define by a finite list of numbers (the taps b₀, b₁, …, bₖ).

📏 Finite
The tap list b₀ … bₖ ends, so its impulse response has a fixed length — unlike an IIR, whose feedback makes the response run on forever (Session 9).
🎯 Impulse Response
Feed one impulse δ and out come exactly the taps. So the taps ARE h — the impulse response from page 10. That is the ‘impulse response’ in the name.
➡️ Feedforward
The output is only a weighted sum of inputs — no past output loops back. No feedback ⇒ an FIR is always stable.
🔑

The moving average is the simplest FIR — every tap = 1/N. Free up the taps and you can design any filter → that is Session 8.

1 /
E · FIR Filter The moving average is an FIR filter

An FIR filter is a weighted sum of inputs. The moving average is just the case where every coefficient equals 1/N.

✅

The moving average is the simplest FIR filter.

E · FIR Filter FIR = feedforward only, no feedback
🔁

z⁻¹ = one-sample delay (holds the value, releases it next step) — chaining them gives x[n−1], x[n−2], …. The signal flows forward only, no line loops back — that "no feedback" is what makes it FIR (vs IIR in Session 9).

The moving average is an FIR whose coefficients are all equal. Free up the coefficients and you can design any FIR filter.

🚀

That freedom is the whole subject of Session 8.

🔧

FIR filters run inside headphones, EQ apps, and hearing aids — each designed by choosing the right coefficients.

⚙️

More taps make a sharper filter — but each tap costs a multiply. Hardware DSP chips have a limited tap budget, so filter design is always a trade-off.

F · Edges & Padding Zero padding — the simple default

Pretend the signal is zero beyond its edges. Then the kernel can slide off the ends and convolution works as usual.

⚠️

Simple default — but the edges get darker because you averaged in zeros.

1 / 89
F · Edges & Padding Output length: valid · same · full
📏

Red columns are edge outputs (kernel hangs off x) — computed by padding x with a 0; the values 1, 3 are real outputs, not the pad. Interior [3, 5] needs no pad = valid. same & full keep padded edges; valid drops them.

1 / 89
F · Edges & Padding Reflect & replicate — natural edges
Replicate

repeat the edge value: [a | a, b, c]

Reflect

mirror across the edge (a not repeated): [b | a, b, c]

e.g. [10,20,30,40] · pad 2  →  replicate [10,10 | 10,20,30,40 | 40,40]  ·  reflect [30,20 | 10,20,30,40 | 30,20]
🖼️

Both fill the edge from real signal values → no dark border like zero padding makes. That's why reflect / replicate are preferred for images.

1 / 89
F · Edges & Padding 🌍 Padding in image processing
🖼️

Image filters use reflect/replicate padding to avoid dark borders — the edges stay natural.

F · Edges & Padding
💻 LAB · Run — FIR Taps & Border Modes

Apply an FIR filter, then see how the edges are handled by the padding mode.

lab.py
import numpy as np
print(np.convolve([3, 5, 8], [1, -1]))        # FIR difference → [ 3  2  3 -8]
x = [1, 2, 3];  h = [1, 1]                # a length-2 box FIR
for m in ["full", "same", "valid"]:        # border / padding modes
    print(m, np.convolve(x, h, m))         # [1 3 5 3] / [1 3 5] / [3 5]
🎛️

An FIR is just its taps h (output = x ∗ h, always stable, no feedback). The mode decides the edges — full keeps every overlap, valid only the complete ones.
